Let the skill write the first draft

The guide explains how to order a design doc. The tech-design-doc skill applies those same rules for you.

You describe the system in plain words. Your AI agent picks an outline, writes the doc in Markdown, draws the diagrams, and checks every diagram before it hands the doc back. It works in Claude Code, Tencent CodeBuddy, GitHub Copilot and OpenAI Codex.

You bring the decision. The skill brings the structure.

The skill can’t know why you chose one design over another. Tell it what you chose and what you rejected. It builds the rest of the doc around that.

The skill carries a short copy of this guide. The agent reads it before it writes a single section. Here is how each part of the guide shows up in the doc you get.

What it adds on top

The guide tells you which diagram to draw. The skill also draws it, and checks it.

Cloud diagrams with the real icons

For a deployment diagram, the skill uses the official AWS, Azure and Google Cloud icons.

One small JSON file gives you an SVG, a PNG, an editable draw.io file and the lines to paste into the doc.

A check before you see it

The skill opens every diagram in a hidden Chrome window and measures it. It looks for boxes that overlap, labels with no room, and icons cut off at the edge.

It fixes each problem and runs the check again. It stops at “0 FAIL” and tells you how many diagrams it checked.

An HTML page, if you want one

Markdown is the main output, ready for Confluence. Ask for HTML too, and you also get a standalone page with the same names, steps and failure paths as the Markdown.

What you still do

The skill gives you a well-ordered first draft. These parts only you can supply.

  • The decision, and what you rejected. Give the one fact that ruled out each option. “Kafka needs a team to run it, and we have two engineers” is enough.
  • The numbers. Budget, latency targets, data volume, cost per month. The skill can’t invent them, and reviewers will ask.
  • Owners for open questions. A name and a date for each one.
  • A real review. The check makes sure every diagram is readable. It can’t tell you if a diagram is correct. Read it as your reviewers will.

Try it

Install the skill. In Claude Code, run:

claude plugin marketplace add whitewhiteqq/tech-design-doc
claude plugin install tech-design-doc@tech-design-doc

For CodeBuddy, Copilot or a manual copy, see the install steps in the README. For Codex, use option 3 there, npx skills add. Cloud diagrams also need the vendor icon packs, a one-time download.

Then ask in plain words. Each prompt below leads to one of the eight outlines. Put your decision in the prompt, and the first draft gets much better.

OutlineAsk your agent
1 · New system design “Write a design doc for a new notification service. We chose a queue over direct calls, because the email provider is often slow. Markdown for Confluence.”
2 · Feature / change “Write a design doc for adding refunds to the checkout service. Show the checkout component before and after.”
3 · Security / access “Write an access-control design for the support dashboard. Which roles can see which customer fields?”
4 · Migration “Write a plan to move the reports database from MySQL to Postgres, with cutover and rollback steps.”
5 · Integration “Write an integration design for a payment provider’s refund API.”
6 · Data pipeline “Write a design for the daily sales report pipeline. Start from who uses the report.”
7 · ADR “Write an ADR: we will filter rows in the database, not in the API.”
8 · Handover / runbook “Write a handover runbook for the order service, with one block per alert.”

If you don’t say Markdown or HTML, the skill asks you once.

What you get back

  • The doc, as a Markdown file, in the order of the outline it picked.
  • An img/ folder next to it, if the doc has a cloud deployment diagram, with the SVG, PNG and draw.io files the doc links to.
  • A check result in the agent’s reply, such as “6 diagrams checked, 0 FAIL”.
  • An HTML page, only if you asked for one.
